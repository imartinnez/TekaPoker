1¿Qué es TekaPoker y cómo está organizado?

TekaPoker es una aplicación web que resuelve un problema muy concreto: al terminar una partida de póker, ¿quién le debe dinero a quién, y cuánto?

Introduces lo que ha puesto cada jugador (el buy-in) y las fichas con las que termina, y el programa te dice exactamente qué transferencias hay que hacer para que todo quede saldado con el mínimo número de pagos. Además guarda un historial completo, un ranking, estadísticas de cada jugador y un análisis del grupo con un asistente de IA.

2Arquitectura: frontend, Supabase y la función de IA

La app no tiene un servidor propio que haya que mantener encendido. El frontend habla directamente con Supabase para todos los datos, y el cálculo de la liquidación ocurre en el propio navegador. La única pieza de servidor es una pequeña función para el chat de IA.

i
¿Por qué una función serverless solo para la IA?
La clave de la API de IA es secreta y no puede ir en el navegador (cualquiera podría verla). Por eso el navegador llama a una función propia en Vercel (frontend/api/chat.js), que es la única que conoce la clave y habla con el proveedor de IA. Es la única parte que se ejecuta en un servidor, y solo cuando usas el chat.

↕

El cálculo de quién paga a quién se hace en el navegador con JavaScript (sin red). Los datos van a Supabase. El chat de IA pasa por la función serverless, que añade el contexto y consulta al modelo.

3La base de datos en Supabase

Supabase es una base de datos PostgreSQL en la nube que expone automáticamente una API. Tú defines las tablas y Supabase se encarga del resto. El archivo supabase/schema.sql contiene el SQL que hay que ejecutar una vez.

players — Jugadores registrados

CREATE TABLE players (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT NOT NULL UNIQUE,   -- nombre único
  avatar_color TEXT NOT NULL DEFAULT '#4ade80',
  created_at   TIMESTAMPTZ DEFAULT now()
);

games — Partidas jugadas

CREATE TABLE games (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  played_at     TIMESTAMPTZ DEFAULT now(),
  buy_in        NUMERIC NOT NULL,
  total_players INTEGER NOT NULL,
  notes         TEXT
);

game_players — Resultado de cada jugador en cada partida

CREATE TABLE game_players (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  game_id     UUID REFERENCES games(id) ON DELETE CASCADE,
  player_id   UUID REFERENCES players(id) ON DELETE CASCADE,
  points      NUMERIC NOT NULL,
  final_money NUMERIC NOT NULL,
  net         NUMERIC NOT NULL   -- positivo = ganó, negativo = perdió
);

transactions — Pagos para saldar la partida

CREATE TABLE transactions (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  game_id        UUID REFERENCES games(id) ON DELETE CASCADE,
  from_player_id UUID REFERENCES players(id) ON DELETE CASCADE,
  to_player_id   UUID REFERENCES players(id) ON DELETE CASCADE,
  amount         NUMERIC NOT NULL
);
!
El buy-in por jugador y las recompras no necesitan tablas nuevas
Aunque cada jugador pueda poner una cantidad distinta y haya recompras entre jugadores, todo queda reflejado en el campo net de game_players y en transactions. Por eso el esquema no cambia.

4Acceso con contraseña

La app está protegida por una contraseña sencilla para que no entre cualquiera a modificar los datos. No es seguridad fuerte, solo un candado básico.

  • La pantalla pages/Login.jsx comprueba la contraseña y, si es correcta, guarda una marca de sesión en localStorage.
  • En App.jsx, un componente ProtectedLayout redirige a /login si no hay sesión activa.
  • El botón Salir de la barra inferior borra la sesión y vuelve al login.
!
La contraseña no se documenta
Por motivos obvios, la contraseña concreta no se escribe en esta guía ni en el README. Está definida en el código de la pantalla de login.

5El cálculo: buy-in por jugador y recompras

El cálculo está en frontend/src/services/calculator.js. La función recibe la lista de jugadores (cada uno con sus fichas y su buy-in) y, opcionalmente, las recompras entre jugadores.

Paso 1 — Valor de cada ficha

const totalPoints = players.reduce((s, p) => s + p.points, 0)
const totalMoney  = players.reduce((s, p) => s + p.buyIn,  0)  // suma de buy-ins
const valuePerPoint = totalMoney / totalPoints

El bote es la suma de los buy-ins de todos. Como cada jugador lleva su propio buyIn, se admiten cantidades distintas por persona.

Paso 2 — Dinero final y ganancia neta de cada jugador

const balances = players.map(p => {
  const finalMoney = p.points * valuePerPoint
  const net        = finalMoney - buyInEfectivo(p)   // ver recompras
  return { ...p, finalMoney, net }
})

Paso 3 — Liquidación con el mínimo de pagos

// Acreedores (ganan) y deudores (pierden), ordenados de mayor a menor
const creditors = balances.filter(p => p.net >  0.01).sort((a,b) => b.net - a.net)
const debtors   = balances.filter(p => p.net < -0.01).sort((a,b) => a.net - b.net)

// El mayor deudor paga al mayor acreedor; quien llega a 0 avanza al siguiente
while (quedan acreedores && quedan deudores) {
  amount = Math.min(creditor.net, Math.abs(debtor.net))
  transactions.push({ from: debtor, to: creditor, amount })
}

Recompras entre jugadores

A veces un jugador se queda sin fichas y, como ya no quedan en la caja, le compra fichas a otro jugador y se lo paga al liquidar (no en el momento). Esto se registra en la pantalla de nueva partida.

i
La idea clave
Esas fichas ya estaban en juego, así que el bote no cambia. Lo que cambia es el buy-in efectivo: sube el del comprador (debe ese dinero) y baja el del vendedor (ya lo cobró al vender sus fichas).
buyInEfectivo = buyIn + (fichas compradas a otros) - (fichas vendidas a otros)

Así la deuda por las fichas se combina automáticamente con el resultado del juego y aparece en los pagos finales, sin pagos aparte. La suma de todos los net sigue siendo exactamente 0.

♠
Ejemplo
4 jugadores ponen 10 € cada uno (bote 40 €). A se queda sin fichas y compra 10 € a B. Si A acaba perdiendo y B ganando, la app calcula que A le paga 5 € a B, importe que ya combina la compra de fichas con el resultado de la partida.

7Las pantallas de la app

La barra inferior tiene cinco pestañas: Inicio, Nueva, Historial, Ranking y Análisis, más el botón Salir. Las pantallas de Jugadores y Caja de fichas se abren desde accesos directos en Inicio.

Login

Pantalla de acceso con contraseña. Hasta que no se valida, no se puede entrar al resto de la app.

Inicio (Home)

Estadísticas en tiempo real: total de partidas, total de jugadores, mayor ganador y última partida. Botón grande de "Nueva partida" y accesos directos a Jugadores y Caja de fichas.

Nueva partida (NewGame)

Selección de jugadores como tarjetas. Se indica un buy-in por defecto que se aplica al seleccionar a cada jugador, pero se puede ajustar individualmente. Cada jugador tiene su campo de buy-in y de fichas finales. Debajo hay una sección de recompras entre jugadores (quién compró fichas a quién y por cuánto).

Resultados (Results)

Muestra el resultado de cada jugador en verde/rojo, las recompras registradas y la lista de pagos para saldar. Botón para guardar la partida en Supabase.

Historial (History)

Lista de partidas guardadas, más reciente primero, cada una expandible. Permite borrar con confirmación.

Ranking

Podio para el top 3 y tabla completa ordenada por ganancias. Al tocar un jugador se abren sus estadísticas.

Análisis (Analytics)

Página de analíticas del grupo y chat de IA. Se detalla en la sección 9.

Caja de fichas (ChipCase)

Configuración del set de fichas y reparto por puntos. Se detalla en la sección 8.

Jugadores (Players)

Lista de jugadores registrados. Permite añadir nuevos y borrar los que no tienen partidas.

8La caja de fichas (por puntos)

Esta pantalla ayuda a repartir las fichas físicas. Importante: las fichas valen puntos, no euros.

i
Cómo funciona
Cada color tiene un valor en puntos (por defecto blanca 1, roja 2, verde 5, azul 10, negra 20), editable porque a veces cambiamos el valor de algún color. Las fichas se reparten a partes iguales entre los jugadores, y el buy-in determina cuánto vale cada punto.
fichasPorJugador = floor(cantidad / nºJugadores)   // para cada color
puntosPorJugador = suma de (fichasPorJugador × valorEnPuntos)
valorPorPunto    = buyIn / puntosPorJugador          // en euros

Como todos arrancan con el mismo stack de puntos, el valor de un stack completo siempre equivale al buy-in. La pantalla muestra los puntos por jugador, el valor por punto, el reparto por color y la reserva que queda en la caja (útil para recompras). La configuración se guarda en el navegador (localStorage), así que se ajusta una vez por dispositivo.

9Analíticas y analista IA

Analíticas del grupo

A partir de todas las partidas, services/analytics.js calcula:

SecciónQué muestra
Evolución del dinero acumuladoGráfica de líneas con el acumulado de cada jugador; al elegir un jugador, su línea se resalta
Comparador de jugadoresGráfica de barras que compara a todos en la métrica elegida (neto total, media, win-rate, volatilidad o partidas)
ConsistenciaRanking por volatilidad: menor variación = resultados más estables
Tendencia / rachaSi un jugador está en alza, en baja o estable según sus últimas partidas
Partidas por nº de jugadoresCuántas partidas se jugaron con cada número de jugadores en mesa

El analista IA

Un chat donde puedes preguntar en lenguaje natural sobre los datos del grupo. El selector "¿Quién eres?" personaliza las respuestas desde la perspectiva de un jugador.

✓
Por qué no se inventa los datos
Funciona como un RAG sencillo: el frontend calcula un resumen estructurado de las estadísticas reales y se lo envía al modelo como contexto. Las instrucciones obligan a usar solo esos datos, a decir "No tengo ese dato registrado" cuando algo no está, y a no inventar cifras. Se ejecuta con temperatura baja para respuestas estables.

Flujo del chat

Analytics.jsx → services/ai.js → POST /api/chat → API de IA (Groq) → respuesta

La función frontend/api/chat.js es la única que conoce la clave de la IA (variable de entorno del servidor). El navegador nunca la ve.

!
En local el chat no responde
La función serverless solo se ejecuta en Vercel (o con vercel dev). Con npm run dev el resto de la app funciona, pero el chat de IA solo responde una vez desplegado.

10Cómo poner en marcha el proyecto

PARTE 1 — Crear la base de datos en Supabase

  1. Ve a supabase.com y crea una cuenta gratuita.
  2. Crea un New project. Nombre: tekapoker. Elige región de Europa. Espera ~2 minutos.
  3. Ve a SQL Editor → New query.
  4. Copia el contenido de supabase/schema.sql, pégalo y pulsa Run.
  5. Ve a Project Settings → API y copia el Project URL y la anon/public key.

PARTE 2 — Configurar las credenciales en local

Crea el archivo frontend/.env (copia de .env.example):

VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
!
El archivo .env nunca debe subirse a GitHub
Contiene credenciales. Ya está en el .gitignore para evitar subirlo por accidente.

PARTE 3 — Arrancar en local

cd frontend
npm install      # solo la primera vez
npm run dev      # http://localhost:5173

11Cómo desplegar en internet (Vercel)

PARTE 1 — Subir el código a GitHub

git add -A
git commit -m "Actualización"
git push origin main

PARTE 2 — Conectar con Vercel

  1. Ve a vercel.com y entra con tu cuenta de GitHub.
  2. Importa el repositorio TekaPoker.
  3. Configura Root Directory como frontend (muy importante; también permite que se despliegue la carpeta api/).
  4. En Environment Variables añade las de Supabase (VITE_SUPABASE_URL, VITE_SUPABASE_ANON_KEY) y, para el chat, GROQ_API_KEY (la clave de IA se obtiene en console.groq.com).
  5. Pulsa Deploy. En 1-2 minutos tendrás una URL pública.
+
Añadir a la pantalla de inicio del móvil
En Safari (iPhone): compartir → "Añadir a pantalla de inicio". En Chrome (Android): menú → "Añadir a pantalla de inicio". Funcionará como una app, sin barra del navegador.
!
La clave de IA solo se configura en Vercel
GROQ_API_KEY es secreta y se usa solo en el servidor. No se escribe en el código ni en esta guía.

12Ejemplo completo: una partida de principio a fin

♣
Escenario
3 amigos, buy-in 10 € cada uno (30 € en el bote)
Alicia → 150 pts · Bob → 90 pts · Carol → 60 pts
  1. Entra con la contraseña y abre la app desde el móvil.
  2. Pulsa "Nueva partida". Aparecen los jugadores registrados.
  3. Selecciona a Alicia, Bob y Carol. Quedan marcadas con borde verde.
  4. Pon el buy-in por defecto (10). Ajusta el de algún jugador si puso más, y registra las recompras entre jugadores si las hubo.
  5. Introduce las fichas finales de cada uno y pulsa "Calcular":
    JugadorPuntosDinero finalNet
    Alicia15015,00 €+5,00 €
    Bob909,00 €−1,00 €
    Carol606,00 €−4,00 €
    Pagos: Carol → Alicia 4,00 € · Bob → Alicia 1,00 €
  6. Pulsa "Guardar partida". Se escribe en Supabase.
  7. Ve a Historial para ver la partida, a Ranking para la clasificación, y a Análisis para las gráficas del grupo y preguntar al analista IA.
