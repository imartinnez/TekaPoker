1¿Qué es TekaPoker y cómo está organizado?

TekaPoker es una aplicación web que resuelve un problema muy concreto: al terminar una partida de póker, ¿quién le debe dinero a quién, y cuánto?

Introduces los puntos finales de cada jugador y el programa te dice exactamente qué transferencias hay que hacer para que todo quede saldado con el mínimo número de pagos posible. Además guarda un historial completo y estadísticas de cada jugador a lo largo del tiempo.

2La nueva arquitectura: sin backend propio

La versión anterior tenía un servidor Python que había que mantener encendido. La nueva versión elimina ese servidor por completo.

💡
¿Por qué quitamos el backend Python?
El backend hacía dos cosas: calcular los pagos (matemáticas puras, sin necesidad de servidor) y guardar datos (que ahora hace Supabase directamente). Al eliminar esas dos responsabilidades, el backend se vuelve innecesario.

El cálculo de quién paga qué ocurre directamente en el navegador (JavaScript). Solo los datos —jugadores, partidas, estadísticas— van a Supabase.

3La base de datos en Supabase

Supabase es una base de datos PostgreSQL en la nube que además expone automáticamente una API REST. No tienes que escribir ningún servidor: tú defines las tablas y Supabase se encarga del resto.

Las 4 tablas del proyecto

players — Jugadores registrados

CREATE TABLE players (
  id           UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  name         TEXT NOT NULL UNIQUE,   -- nombre único, no puede repetirse
  avatar_color TEXT NOT NULL DEFAULT '#4ade80',
  created_at   TIMESTAMPTZ DEFAULT now()
);

Un jugador se registra una sola vez y queda guardado para siempre, a menos que se borre manualmente. El avatar_color es el color del círculo de avatar que se le asigna al crearlo.

games — Partidas jugadas

CREATE TABLE games (
  id            UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  played_at     TIMESTAMPTZ DEFAULT now(),
  buy_in        NUMERIC NOT NULL,     -- lo que pagó cada jugador para entrar
  total_players INTEGER NOT NULL,
  notes         TEXT                  -- campo opcional
);

game_players — Resultado de cada jugador en cada partida

CREATE TABLE game_players (
  id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  game_id     UUID REFERENCES games(id) ON DELETE CASCADE,
  player_id   UUID REFERENCES players(id) ON DELETE CASCADE,
  points      NUMERIC NOT NULL,
  final_money NUMERIC NOT NULL,
  net         NUMERIC NOT NULL   -- positivo = ganó, negativo = perdió
);

ON DELETE CASCADE significa que si borras una partida, se borran automáticamente todas sus filas en esta tabla. No hay que hacer nada extra.

transactions — Pagos para saldar la partida

CREATE TABLE transactions (
  id             UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  game_id        UUID REFERENCES games(id) ON DELETE CASCADE,
  from_player_id UUID REFERENCES players(id) ON DELETE CASCADE,
  to_player_id   UUID REFERENCES players(id) ON DELETE CASCADE,
  amount         NUMERIC NOT NULL
);
⚠️
Importante: ejecutar el schema.sql en Supabase
El archivo supabase/schema.sql del proyecto contiene exactamente este SQL. Tienes que pegarlo en el SQL Editor de Supabase y ejecutarlo una sola vez para crear las tablas. Sin este paso la app no funcionará.

4La lógica de cálculo en JavaScript

El algoritmo que antes vivía en Python ahora vive en frontend/src/services/calculator.js. La lógica es exactamente la misma, solo cambia el lenguaje.

🃏
Ejemplo que usaremos
3 jugadores, buy-in €10 (€30 en el bote)
Alicia → 120 pts  ·  Bob → 80 pts  ·  Carol → 40 pts

Paso 1 — Sumar todos los puntos

const totalPoints = players.reduce((sum, p) => sum + p.points, 0)
// 120 + 80 + 40 = 240

reduce() recorre la lista acumulando valores. Empieza en 0 y suma el campo points de cada jugador.

Paso 2 — Bote total y valor por punto

const totalMoney   = buyIn * players.length   // €10 × 3 = €30
const valuePerPoint = totalMoney / totalPoints  // €30 / 240 = €0.125 por punto

Paso 3 — Dinero final y ganancia neta de cada jugador

const balances = players.map(p => {
  const finalMoney = p.points * valuePerPoint          // Alicia: 120 × 0.125 = €15
  const net        = Math.round((finalMoney - buyIn) * 100) / 100
  // Alicia: €15 − €10 = +€5  |  Bob: €10 − €10 = €0  |  Carol: €5 − €10 = −€5
  return { ...p, finalMoney, net }
})

Paso 4 — Separar en acreedores y deudores

const creditors = balances.filter(p => p.net >  0.01)   // los que ganaron
const debtors   = balances.filter(p => p.net < -0.01)   // los que perdieron

Paso 5 — Algoritmo voraz (greedy): mínimo de transferencias

// Ordenar de mayor a menor importe
creditors.sort((a, b) => b.net - a.net)
debtors.sort((a, b)   => a.net - b.net)   // los más negativos primero

while (creditors hay pendientes && debtors hay pendientes) {
  amount = Math.min(creditor.net, Math.abs(debtor.net))
  transactions.push({ from: debtor.name, to: creditor.name, amount })
  // Restar el importe de ambos saldos
  // Avanzar al siguiente cuando alguien llega a 0
}

Resultado con el ejemplo: Una sola transferencia — Carol paga €5 a Alicia. Bob queda en €0, no paga ni cobra nada.

5Los servicios: base de datos y cálculo

services/supabase.js — La conexión

import { createClient } from '@supabase/supabase-js'

const supabaseUrl = import.meta.env.VITE_SUPABASE_URL
const supabaseKey = import.meta.env.VITE_SUPABASE_ANON_KEY

export const supabase = createClient(supabaseUrl, supabaseKey)

import.meta.env lee las variables del archivo .env. Las credenciales nunca se escriben directamente en el código.

services/database.js — Operaciones con la BD

Contiene todas las funciones para leer y escribir en Supabase:

Función¿Qué hace?
getPlayers()Devuelve todos los jugadores ordenados por nombre
createPlayer(name)Crea un jugador nuevo con color de avatar aleatorio
deletePlayer(id)Borra un jugador. Falla con mensaje claro si tiene partidas
saveGame(data)Guarda la partida completa: game + game_players + transactions

deleteGame(id)Borra una partida (el cascade borra el resto automáticamente)
getPlayerStats(id)Estadísticas completas de un jugador (ver sección 7)
getGlobalRanking()Todos los jugadores con stats agregadas, ordenados por ganancia

6Los componentes reutilizables

Navbar.jsx — Barra inferior de navegación

Cinco pestañas fijas en la parte inferior de la pantalla: Inicio, Nueva partida, Historial, Ranking, Jugadores. Diseñada para pulgares: botones grandes, siempre visibles. La pestaña activa se ilumina en verde.

Toast.jsx — Notificaciones emergentes

Mensajes que aparecen brevemente en la parte superior y desaparecen solos. Se usan para confirmar acciones ("Partida guardada ✓") o mostrar errores ("No se puede eliminar este jugador").

ConfirmDialog.jsx — Diálogo de confirmación

Modal que aparece antes de cualquier acción destructiva (borrar partida, borrar jugador). Requiere confirmación explícita para evitar accidentes.

LoadingSpinner.jsx — Indicador de carga

Círculo giratorio que aparece mientras se espera respuesta de Supabase.

7Las pantallas de la app

Inicio (Home)

Estadísticas en tiempo real leídas de Supabase: total de partidas, total de jugadores, mayor ganador histórico y última partida jugada. Botón grande de acceso rápido a nueva partida.

Nueva partida (NewGame)

Carga los jugadores registrados de Supabase y los muestra como tarjetas seleccionables. Tocar una tarjeta selecciona/deselecciona al jugador. El botón "+ Añadir nuevo jugador" abre un formulario inline que crea el jugador en la BD y lo selecciona automáticamente. Botón "Calcular" fijo en la parte inferior de la pantalla.

Resultados (Results)

Muestra las ganancias/pérdidas en verde/rojo y la lista de pagos a realizar. Botón "Guardar partida" que escribe en Supabase.

Historial (History)

Lista de partidas guardadas, más reciente primero. Cada tarjeta se puede expandir para ver detalles. Botón de borrar con diálogo de confirmación.

Ranking

Pódium visual para el top 3 (🥇🥈🥉) y tabla completa ordenada por ganancias totales. Tocar cualquier jugador abre su página de estadísticas.

Jugadores (Players)

Lista completa de jugadores registrados con fecha de incorporación y color de avatar. Permite añadir nuevos jugadores o borrar los que no tienen partidas asociadas.

Estadísticas de jugador (PlayerStats)

La pantalla más completa de la app. Incluye:

8Cómo poner en marcha el proyecto

PARTE 1 — Crear la base de datos en Supabase

  1. Ve a supabase.com y crea una cuenta gratuita.
  2. Haz clic en "New project". Nombre: tekapoker. Elige región West EU. Espera ~2 minutos.
  3. En el menú lateral ve a SQL Editor → New query.
  4. Copia el contenido de supabase/schema.sql y pégalo. Haz clic en Run. Deberías ver "Success".
  5. Ve a Project Settings → API y copia el Project URL y la anon/public key.

PARTE 2 — Configurar las credenciales en local

Crea el archivo frontend/.env (copia de .env.example) con tus valores:

VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
⚠️
El archivo .env nunca debe subirse a GitHub
Contiene credenciales de acceso a tu base de datos. Ya está incluido en el .gitignore para evitar subirlo por accidente.

PARTE 3 — Arrancar en local

Solo necesitas un terminal (ya no hay backend que arrancar por separado):

cd frontend
npm install      # solo la primera vez
npm run dev      # arranca en http://localhost:5173

9Cómo desplegar en internet (Vercel)

Una vez desplegada, la app funciona 24/7 desde cualquier móvil sin que tu ordenador esté encendido.

PARTE 1 — Subir el código a GitHub

git add .
git commit -m "Migrate to Supabase"
git push origin main

PARTE 2 — Conectar con Vercel

  1. Ve a vercel.com y entra con tu cuenta de GitHub.
  2. Haz clic en "Add New Project" e importa el repositorio tekapoker.
  3. Configura Root Directory como frontend (muy importante).
  4. En Environment Variables añade las dos variables de Supabase:
    VITE_SUPABASE_URL y VITE_SUPABASE_ANON_KEY
  5. Haz clic en Deploy. En 1-2 minutos tendrás una URL pública.
📱
Añadir a la pantalla de inicio del móvil
En Safari (iPhone): compartir → "Añadir a pantalla de inicio".
En Chrome (Android): menú → "Añadir a pantalla de inicio".
Funcionará como una app nativa, sin barra del navegador.

10Ejemplo completo: una partida de principio a fin

🃏
Escenario
3 amigos, buy-in €10 (€30 en el bote)
Alicia → 150 pts · Bob → 90 pts · Carol → 60 pts
  1. Abre la app desde el móvil. La pantalla de inicio muestra las estadísticas acumuladas.
  2. Pulsa "Nueva partida". Aparecen los jugadores ya registrados como tarjetas.
  3. Selecciona a Alicia, Bob y Carol tocando sus tarjetas. Quedan marcadas con un borde verde.
  4. Escribe el buy-in: 10 e introduce los puntos de cada uno.
  5. Pulsa "Calcular". El resultado aparece al instante — sin llamada al servidor.
    JugadorPuntosDinero finalNet
    Alicia150€15,00+€5,00
    Bob90€9,00−€1,00
    Carol60€6,00−€4,00
    Pagos: Carol → Alicia €4,00 · Bob → Alicia €1,00
  6. Pulsa "Guardar partida". Los datos se escriben en Supabase. Aparece un toast de confirmación.
  7. Ve a Historial. La partida aparece en la lista. Expándela para ver los detalles.
  8. Ve a Ranking. Alicia encabeza la clasificación con +€5,00. Toca su nombre para ver sus estadísticas detalladas con la gráfica de evolución.
