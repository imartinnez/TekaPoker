1¿Qué es TekaPoker y cómo está organizado?

TekaPoker es una aplicación web que resuelve un problema muy concreto: al terminar una partida de póker, ¿quién le debe dinero a quién, y cuánto?

En lugar de hacer cuentas a mano, abres TekaPoker, introduces los puntos finales de cada jugador y el programa te dice exactamente qué transferencias hay que hacer para que todo quede saldado.

La arquitectura: dos partes que trabajan juntas

🍽️
Analogía del restaurante
El frontend es el salón: lo que ve el cliente (botones, pantallas, colores). El backend es la cocina: donde ocurren los cálculos reales. El cliente no entra a la cocina, pero sí recibe el resultado de lo que se prepara allí.
ParteTecnología¿Qué hace?
BackendPython + FastAPIRecibe los datos de la partida, hace los cálculos matemáticos y devuelve los resultados
FrontendReact + ViteMuestra la interfaz al usuario: formularios, resultados, historial, ranking

2Los archivos de configuración

.gitignore — Qué no subir a GitHub

Git es un programa que guarda el historial de cambios de tu código (como un "Ctrl+Z" infinito). Cuando subes el proyecto a GitHub, Git sube todos los archivos que encuentra, a menos que los excluyas en .gitignore.

node_modules/   # Carpeta enorme con librerías (puede pesar cientos de MB)
dist/           # La versión compilada del frontend (se genera automáticamente)
.env            # ¡IMPORTANTE! Contiene URLs y claves privadas, nunca debe subirse
__pycache__/    # Archivos temporales que Python crea al ejecutarse
*.log           # Registros de errores (archivos de texto con información técnica)
⚠️
El archivo .env nunca debe subirse a GitHub
El .env puede contener contraseñas, claves de API o URLs internas. Si lo subes accidentalmente a un repositorio público, cualquiera puede leerlo. Por eso está en el .gitignore.

.env.example — La plantilla de configuración

Los archivos .env (de environment, que significa "entorno") son hojas de configuración que cambian según dónde se ejecute la app: en tu ordenador local o en un servidor en internet.

frontend/.env.example:

Para usarlos: copia el archivo, renómbralo a .env (sin .example) y rellena los valores. El .env real no se sube a GitHub.

3El Backend — Python con FastAPI

backend/main.py — El punto de entrada del servidor

Este archivo arranca el servidor y define el único endpoint (dirección) que acepta peticiones.

1. Importar librerías

from fastapi import FastAPI, HTTPException
from fastapi.middleware.cors import CORSMiddleware
from pydantic import BaseModel, field_validator
from logic.calculator import calculate_settlements

import es como "abrir la caja de herramientas y sacar lo que necesitas".

2. Crear la aplicación

app = FastAPI(title="TekaPoker API", version="1.0.0")

Crea el servidor. La variable app representa toda la aplicación.

3. Configurar CORS

app.add_middleware(
    CORSMiddleware,
    allow_origins=["http://localhost:5173", ...],
    allow_methods=["*"],
    allow_headers=["*"],
)

CORS es un mecanismo de seguridad del navegador: por defecto, una página web no puede llamar a un servidor en otro puerto. Este middleware lo permite explícitamente para el frontend.

4. Modelos de datos (validación automática)

class Player(BaseModel):
    name: str      # str = texto
    points: float  # float = número con decimales

class GameRequest(BaseModel):
    players: List[Player]   # lista de jugadores
    buy_in: float           # cantidad en euros

    # Validación extra: al menos 2 jugadores
    @field_validator("players")
    def must_have_at_least_two(cls, players):
        if len(players) < 2:
            raise ValueError("At least 2 players are required")
        return players

Pydantic valida automáticamente que los datos recibidos tienen el tipo correcto. Si alguien envía points: "hola", el servidor devuelve un error claro sin que tú tengas que comprobarlo.

5. Los endpoints

# GET / → "¿hay alguien en casa?"
@app.get("/")
def root():
    return {"message": "TekaPoker API is running!"}

# POST /calculate → el endpoint principal
@app.post("/calculate")
def calculate(request: GameRequest):
    players_data = [
        {"name": p.name, "points": p.points}
        for p in request.players
    ]
    result = calculate_settlements(players_data, request.buy_in)
    return result

Una ruta es una dirección a la que puedes llamar. @app.post("/calculate") significa "cuando alguien envíe datos a /calculate, ejecuta esta función". FastAPI convierte automáticamente el JSON recibido en objetos Python, y el diccionario devuelto en JSON de respuesta.

4La lógica de cálculo de pagos

backend/logic/calculator.py

Este es el archivo más importante del proyecto. Contiene toda la matemática, explicada paso a paso. Lo vamos a analizar con un ejemplo concreto.

🃏
Ejemplo que usaremos en esta sección
3 jugadores, buy-in €10 cada uno (€30 en el bote)
Alicia → 120 puntos  ·  Bob → 80 puntos  ·  Carol → 40 puntos

Paso 1 — Sumar todos los puntos

total_points = sum(player["points"] for player in players)
# total_points = 120 + 80 + 40 = 240

sum() suma todos los valores. La expresión dentro es un generador: "recorre la lista de jugadores y dame el campo 'points' de cada uno". Necesitamos el total para repartir el dinero proporcionalmente.

Paso 2 — Calcular el bote total

num_players = len(players)          # len() cuenta cuántos elementos hay → 3
total_money = buy_in * num_players   # €10 × 3 = €30

len() cuenta los elementos de una lista. El bote es lo que pagó cada jugador multiplicado por cuántos hay.

Paso 3 — Valor de cada punto

if total_points == 0:
    value_per_point = 0.0        # Protección: evita dividir por cero
else:
    value_per_point = total_money / total_points
# value_per_point = €30 / 240 = €0.125 por punto

El if total_points == 0 protege contra un error matemático: en Python (como en cualquier sistema), no se puede dividir por cero.

Paso 4 — Dinero final de cada jugador

for player in players:
    player["final_money"] = round(player["points"] * value_per_point, 2)

for player in players significa "repite esto para cada jugador de la lista". round(..., 2) redondea a 2 decimales (centavos), evitando números como €14,9999999...

JugadorPuntos× €0,125= Dinero final
Alicia120× 0,125€15,00
Bob80× 0,125€10,00
Carol40× 0,125€5,00

Paso 5 — Ganancia o pérdida neta

net = round(player["final_money"] - buy_in, 2)
# Alicia: €15 − €10 = +€5,00  ← GANÓ
# Bob:    €10 − €10 =  €0,00  ← empató
# Carol:   €5 − €10 = −€5,00  ← PERDIÓ
✅
Comprobación matemática
La suma de todas las ganancias netas siempre debe ser €0. El dinero no desaparece, solo cambia de manos: (+€5) + (€0) + (−€5) = €0.

Paso 6 — Separar en acreedores y deudores

TOLERANCE = 0.01  # 1 céntimo (diferencias menores se ignoran)

creditors = [                          # Jugadores que ganaron → les deben pagar
    {"name": b["name"], "amount": b["net"]}
    for b in balances
    if b["net"] > TOLERANCE
]

debtors = [                            # Jugadores que perdieron → deben pagar
    {"name": b["name"], "amount": abs(b["net"])}
    for b in balances
    if b["net"] < -TOLERANCE
]
# abs(-5) = 5  ← convierte negativo en positivo para facilitar el cálculo
JugadorNetRol
Alicia+€5,00Acreedor (le deben)
Bob€0,00Neutral (ignorado)
Carol−€5,00Deudor (debe pagar)

Paso 7 — El algoritmo voraz (greedy)

El objetivo es producir el mínimo número de transferencias posible para saldar todas las deudas.

# 1. Ordenar de mayor a menor (los más grandes primero)
creditors.sort(key=lambda x: x["amount"], reverse=True)
debtors.sort(key=lambda x: x["amount"], reverse=True)

while cred_index < len(creditors) and debt_index < len(debtors):
    creditor = creditors[cred_index]
    debtor   = debtors[debt_index]

    # 2. La transferencia es el mínimo entre lo que debe el deudor
    #    y lo que le deben al acreedor
    amount = round(min(creditor["amount"], debtor["amount"]), 2)

    transactions.append({
        "from":   debtor["name"],    # el deudor paga
        "to":     creditor["name"],  # el acreedor recibe
        "amount": amount
    })

    # 3. Restar la cantidad transferida de ambos saldos
    creditor["amount"] -= amount
    debtor["amount"]   -= amount

    # 4. Si alguien llegó a 0, pasar al siguiente
    if creditor["amount"] <= TOLERANCE: cred_index += 1
    if debtor["amount"]   <= TOLERANCE: debt_index += 1

Traza del algoritmo con el ejemplo sencillo:

RondaAcreedorDeudorTransferenciaSaldo acreedorSaldo deudor
1Alicia (€5)Carol (€5)€5,00€0 ✓€0 ✓

Resultado: Carol le paga €5 a Alicia. ¡Una sola transferencia!

Ejemplo más complejo (4 jugadores): Dave ganó €10, Alicia ganó €2, Bob perdió €7, Carol perdió €5.

RondaAcreedorDeudorPagoSaldos restantes
1Dave (€10)Bob (€7)€7,00Dave: €3, Bob: €0
2Dave (€3)Carol (€5)€3,00Dave: €0, Carol: €2
3Alicia (€2)Carol (€2)€2,00Todos a €0

Solo 3 transferencias en lugar de las posibles 6 si cada uno pagara a cada uno.

¿Qué es React?

React es una librería de JavaScript para construir interfaces de usuario. La idea clave: defines componentes (bloques reutilizables) y React actualiza la pantalla automáticamente cuando los datos cambian, sin necesidad de recargar la página.

  </BrowserRouter>

  1. Encuentra el <div id="root"> del archivo HTML
  2. Envuelve toda la app en BrowserRouter (el sistema de navegación entre pantallas)
  3. "Renderiza" (dibuja) el componente App dentro de ese div

Los archivos .jsx mezclan JavaScript con etiquetas que parecen HTML (<BrowserRouter>, <App />). A esto se le llama JSX. Vite convierte automáticamente este código en JavaScript puro antes de enviarlo al navegador.

6Los servicios: comunicación y almacenamiento

src/services/api.js — El mensajero

const API_URL = import.meta.env.VITE_API_URL || 'http://localhost:8000'

export async function calculateSettlements(players, buyIn) {
  const response = await fetch(`${API_URL}/calculate`, {
    method: 'POST',                                     // tipo de petición
    headers: { 'Content-Type': 'application/json' },    // formato del mensaje
    body: JSON.stringify({ players, buy_in: buyIn }),   // datos a enviar
  })

  if (!response.ok) throw new Error(detail)  // si hay error, lanzar excepción
  return response.json()                      // convertir respuesta JSON a objeto JS
}
ConceptoExplicación simple
fetchFunción del navegador para hacer peticiones HTTP a servidores, como enviar un SMS
async / await"Espera a que el servidor responda antes de continuar" (el servidor puede tardar)
method: 'POST'Tipo de petición para enviar datos (GET es para pedir datos, POST para enviarlos)
JSON.stringify()Convierte un objeto JavaScript en texto JSON para enviarlo por la red
response.json()Convierte la respuesta JSON de vuelta en un objeto JavaScript

src/services/storage.js — La memoria de la app

Como no hay base de datos, todo se guarda en localStorage: un pequeño cajón de almacenamiento que tiene cada navegador en el ordenador del usuario. Los datos persisten aunque se cierre el navegador.

const KEY = 'tekapoker_games'   // El "nombre del cajón"

// Leer todas las partidas guardadas
export function getGames() {
  const raw = localStorage.getItem(KEY)   // Abre el cajón y lee
  return raw ? JSON.parse(raw) : []        // Si hay algo, lo devuelve; si no, lista vacía
}

// Guardar una partida nueva (la añade al principio)
export function saveGame(gameData) {
  const games = getGames()
  const newGame = { id: String(Date.now()), ...gameData }
  // Date.now() = milisegundos desde 1970, sirve como ID único
  localStorage.setItem(KEY, JSON.stringify([newGame, ...games]))
}

// Borrar una partida por su ID
export function deleteGame(id) {
  const updated = getGames().filter((g) => g.id !== id)
  // filter() crea una lista nueva sin el elemento que tiene ese ID
  localStorage.setItem(KEY, JSON.stringify(updated))
}

// Calcular la clasificación acumulada de todos los juegos
export function getRanking() {
  const map = {}   // diccionario: nombre → { net, games, wins }

  for (const game of getGames()) {
    for (const balance of game.balances) {
      if (!map[balance.name]) map[balance.name] = { net: 0, games: 0, wins: 0 }
      map[balance.name].net   += balance.net   // acumula ganancias totales
      map[balance.name].games += 1
      if (balance.net > 0) map[balance.name].wins += 1
    }
  }

  return Object.values(map).sort((a, b) => b.net - a.net)
  // Convierte el diccionario en lista y ordena de mayor a menor ganancia
}

9Comunicación frontend ↔ backend

Flujo completo de una petición

USUARIO FRONTEND (React) BACKEND (Python) │ │ │ │ Rellena formulario │ │ │ Pulsa Calculate ───────▶│ │ │ │ validate() ✓ │ │ │ setLoading(true) │ │ │ │ │ │─── POST /calculate ─────────▶│ │ │ { players, buy_in } │ │ │ │ FastAPI valida JSON │ │ │ calculate_settlements() │ │ │ → cálculos matemáticos │ │ │ │ │◀── respuesta JSON ────────────│ │ │ { balances, transactions } │ │ │ │ │ │ setLoading(false) │ │ │ navigate('/results') │ │◀─── pantalla resultados │ │

El formato JSON

JSON (JavaScript Object Notation) es texto estructurado que tanto Python como JavaScript entienden perfectamente. Así se ven los datos viajando por la red:

Petición (frontend → backend)
{
  "players": [
    {"name": "Alicia", "points": 120},
    {"name": "Bob",    "points": 80}
  ],
  "buy_in": 10
}
Respuesta (backend → frontend)
{
  "balances": [
    {"name": "Alicia", "net": 5.0},
    {"name": "Bob",    "net": -5.0}
  ],
  "transactions": [
    {"from": "Bob", "to": "Alicia",
     "amount": 5.0}
  ]
}

Arrancar el Backend

cd backend

cd = "Change Directory". Entra en la carpeta backend.

pip install -r requirements.txt

pip es el instalador de paquetes de Python. Descarga FastAPI, Uvicorn y las demás librerías. Solo hay que ejecutarlo la primera vez.

uvicorn main:app --reload
  • uvicorn — el programa que ejecuta el servidor web
  • main:app — "en el archivo main.py, busca la variable llamada app"
  • --reload — reinicia el servidor automáticamente al cambiar el código (ideal para desarrollar)
✅
El servidor está listo cuando ves
INFO: Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

Arrancar el Frontend

Abre un segundo terminal (deja el del backend abierto):

cd frontend
npm install

npm es el instalador de paquetes de Node.js. Descarga todas las librerías de package.json. Solo la primera vez.

npm run dev

Arranca el servidor de desarrollo. Vite compila el código y lo sirve en http://localhost:5173.

✅
El frontend está listo cuando ves
VITE ready in 300ms → Local: http://localhost:5173
Abre esa dirección en el navegador.

11Ejemplo completo: una partida de principio a fin

🃏
Escenario
Tres amigos jugaron al póker. Buy-in: €10 cada uno (€30 en el bote)
Alicia → 150 puntos (le fue bien)  ·  Bob → 90 puntos (regular)  ·  Carol → 60 puntos (le fue mal)
  1. Abre la app en http://localhost:5173. Verás la pantalla de inicio con el título "TekaPoker" y el botón "Start New Game".
  2. Pulsa "Start New Game". La app navega a /new-game con el formulario vacío.
  3. Rellena el formulario:
    CampoValor
    Game nameViernes noche
    Buy-in10
    Player 1 — NameAlicia
    Player 1 — Points150
    Player 2 — NameBob
    Player 2 — Points90
    Player 3 — NameCarol
    Player 3 — Points60
  4. Pulsa "Calculate Settlements". Aparece el spinner. El frontend envía al backend:
    { "players": [{"name":"Alicia","points":150}, {"name":"Bob","points":90}, {"name":"Carol","points":60}], "buy_in": 10 }
  5. El backend calcula:
    JugadorPuntosFinal (× €0,10)Net (− €10)
    Alicia150€15,00+€5,00 ✓ Ganó
    Bob90€9,00−€1,00 ✗ Perdió
    Carol60€6,00−€4,00 ✗ Perdió

    Algoritmo greedy: Alicia (€5) vs Carol (€4) → Carol paga €4. Alicia queda en €1. Alicia (€1) vs Bob (€1) → Bob paga €1. Todos a €0.

  6. La pantalla de resultados muestra:
    JugadorPuntosResultado
    ▲ Alicia150 pts+€5,00
    ▼ Bob90 pts−€1,00
    ▼ Carol60 pts−€4,00

    Pagos a realizar:

    #PagaACantidad
    1CarolAlicia€4,00
    2BobAlicia€1,00
  7. Guarda la partida pulsando "Save Game". Los datos se guardan en localStorage.
  8. Ve a History. Verás la partida "Viernes noche" guardada. Pulsa para expandir y ver los detalles. Si quieres borrarla, pulsa "Delete game" y confirma en el diálogo.
  9. Ve a Ranking. Alicia aparece en primer lugar con +€5,00 en ganancia total.
